# Weekly Plan — Learning Journey

## Purpose

This file describes my weekly learning plan.

The goal is to keep balance between English, Linux, Git, and future DevOps topics.

This plan is flexible. If I am tired or busy, I can do a smaller version.

Main rule:

Consistency is more important than intensity.

---

## Current weekly focus

Current stage:

- System / Linux / Git / Markdown practice: 60%
- English: 40%

This balance is flexible and depends on context.

If I am at home and I have access to my computer, the main focus is Linux, Git, VS Code, terminal, Markdown, and practical technical work.

If I am at work or using only my phone, the main focus is English practice, writing, grammar, and explaining what I did in my technical sessions.

English is still included in technical sessions, but in a lighter form: vocabulary, short phrases, and simple explanations of commands.

At this stage, I should not rush into Docker, Kubernetes, Terraform, or cloud.

First I need strong foundations:

- English grammar automation
- writing practice
- Linux basics
- terminal confidence
- Git habit
- Markdown documentation

---

## Weekly goals

Every week I should try to:

- practice English several times
- write at least 2–3 short texts in English
- review my personal mistakes
- learn or repeat basic Linux commands
- update Markdown notes
- make Git commits
- keep the project clean and organized

---

## Suggested weekly structure

### Monday — English + planning

Focus:

- short English lesson
- grammar practice
- writing task
- update weekly goals

Good topics:

- Past Simple
- Present Simple vs Present Continuous
- real-life writing
- workday story

---

### Tuesday — Linux basics

Focus:

- terminal commands
- files and directories
- paths
- basic command explanations in English

Example:

Command:

pwd

English explanation:

It shows the current directory.

---

### Wednesday — English writing

Focus:

- write 8–10 sentences
- correct 3–5 important mistakes
- add repeated mistakes to English/Mistakes.md

Good topics:

- my day
- Ubuntu setup
- work
- English Journey
- future career

---

### Thursday — Git and Markdown

Focus:

- Git status
- Git add
- Git commit
- Markdown notes
- project structure

Good habit:

At the end of the session, check:

git status

If files changed, make a commit.

---

### Friday — Mixed lesson

Focus:

- English + Linux together
- explain one command in English
- update DevOps/Linux.md

Example:

Command:

ls

English explanation:

It shows files and folders in the current directory.

---

### Saturday — Longer practice or project work

If I have time and energy:

- longer English practice
- Linux practice
- Markdown update
- Git commit
- review progress

If I am tired:

- short review only

---

### Sunday — Review and rest

Focus:

- review what I learned
- update PROGRESS.md
- plan next week
- do not overload

Good question:

What did I improve this week?

---

## Reminder times

I have daily reminders at:

- 10:00
- 12:00
- 16:30
- 21:00

Best learning time:

12:00

When a reminder appears, I should ask myself:

- Do I have time?
- Do I have energy?
- Can I do at least one small step?

I do not have to study four times per day.  
The reminders are there to help me choose a good moment.

---

## 15-minute weekly option

If I have only 15 minutes, I can:

- review one mistake
- write 3 English sentences
- learn one Linux command
- update one Markdown file
- make one small commit

Small progress is still progress.

---

## 30-minute weekly option

If I have 30 minutes, I can:

- do short English practice
- correct mistakes
- learn one Linux/Git topic
- update notes
- commit changes

---

## 60-minute weekly option

If I have 60 minutes, I can:

- practice English conversation
- write 8–10 sentences
- review corrections
- learn Linux or Git
- update project files
- make a Git commit

---

## Weekly review questions

At the end of each week, answer:

1. What did I learn this week?
2. What English mistakes did I repeat?
3. What Linux or Git commands did I practice?
4. What files did I update?
5. What is the next small step?

---

## Minimum weekly result

Even if the week is difficult, I should try to complete at least:

- 1 English writing task
- 1 Linux command explanation
- 1 update in Markdown
- 1 Git commit

This is enough to keep the project alive.

---

## Personal rule

Do not chase perfect weeks.

A normal week with small progress is better than an overloaded week followed by burnout.
