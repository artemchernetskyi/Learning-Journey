# AI collaboration guidelines

## Project purpose

This repository documents Artem's DevOps learning journey.

The repository contains:

- lesson notes;
- practical Linux exercises;
- Bash scripts;
- Git practice;
- future DevOps projects.

## Working style

- Explain changes before making large modifications.
- Use clear, beginner-friendly English.
- Correct Artem's English gently when useful.
- Provide Ukrainian explanations when a topic is confusing.
- Prefer practical terminal exercises.
- Do not skip important fundamentals.
- Keep lessons structured and incremental.

## Repository rules

- Do not modify previous lesson notes unless asked.
- Add new lessons to the end of the appropriate Markdown file.
- Keep the existing lesson-note style.
- Use meaningful file and variable names.
- Quote Bash variables unless there is a clear reason not to.
- Check Bash scripts with `bash -n`.
- Do not commit secrets, API keys, tokens, or passwords.
- Do not run destructive commands without explicit confirmation.

## Git workflow

Before committing:

1. Run relevant tests.
2. Run syntax checks.
3. Review `git diff`.
4. Use a descriptive commit message.
5. Confirm the working tree state after the commit.
